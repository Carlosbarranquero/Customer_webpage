# Prompt — Build a website from a brand brief

> Generic template. Works with any business whose brief is split across four files matching `_soul.md`, `_experience.md`, `_operations.md`, `_visual.md`, plus an images folder. Paste this prompt as-is into a session with access to the project directory and the `frontend-design` skill.

---

## Task

Build **a single-piece website** (one-pager HTML, everything in one `.html` file with inline CSS and JS) for the business described in the four `.md` files available. This is not a default marketing landing: it's a **digital translation of the brand**. It should give the same sensation someone would get walking into the physical space or interacting with the product.

Activate the **`frontend-design`** skill before starting. If the skill is not installed, install it first — search for it in the skill marketplace or load it from the available skill repository before proceeding. Do not skip this step: the page has to feel intentionally designed, not generated by default.

---

## Inputs (mandatory read before coding)

Read the four files **in full** before writing a single line of code. Locate them by suffix in the current directory:

- `*_soul.md` — who they are, tagline, brand promise, personality, tone of voice, positioning, who it's for / what it is not.
- `*_experience.md` — what the customer feels, real quotes, most-cited attributes, why they return, real use cases, honest criticism, writing guidelines.
- `*_operations.md` — business file, hours, offering / menu / services, location, best times to visit, operational notes.
- `*_visual.md` — color palette (with HEX), suggested typography, visual motifs, photography direction, materials and textures, multisensory reference.

**The `*_visual.md` file is the authority on aesthetics.** Don't invent colors or typography beyond what's defined there. If any input is missing or empty, flag it and stop — don't fill gaps with generic content.

---

## Images

There's an image folder in the project (typically `./images/`, `./imagenes/`, `./raw_data/Images/` or similar — find it before starting). Do not assume how many there are or how they're named: **inspect the directory**, list the available files, then decide how to distribute them.

Rules for using them:

1. **Local images only.** No downloading, no generating, no external stock.
2. **Relative paths** from the HTML so the page opens directly from the filesystem.
3. **Every image needs a role.** Before placing it, decide whether it's hero, atmosphere, portrait, detail, transition, gallery or closing. Don't include images just because they exist.
4. If you look at an image and it doesn't match the section you had in mind, **change the section, don't force the image.**
5. Descriptive `alt` in the same language as the rest of the copy, respecting the tone of voice defined in `*_soul.md`.
6. If some images are clearly weak or redundant, omit them. Four strong ones beat twelve mediocre ones.

---

## Creative direction

**This is not a default marketing landing.** Avoid worn-out patterns: purple gradients on white, huge "Book now" buttons, three-column icon grids, testimonials in cards with drop shadows. Lean closer to **an editorial piece, a long-form, or a digital magazine** than to a SaaS template.

Golden rules:

1. **Rhythm matches the tone.** If the brand is slow and contemplative, give it breathing room. If it's energetic and maximalist, controlled density. Pull the rhythm from `*_soul.md` and `*_experience.md`, not from defaults.
2. **Palette from `*_visual.md`.** Respect which colors dominate and which are accents. Accents are accents — they don't become full backgrounds.
3. **Typography**: a pairing with character (display + body), always loaded from Google Fonts or equivalent. Banned by default: `Inter`, `Roboto`, `Arial`, system fonts. If `*_visual.md` suggests a specific direction (script, condensed, classic serif, mono…), follow it.
4. **Atmospheric backgrounds.** Subtle textures, layered transparencies, grain if it fits. Flat colors alone won't do it.
5. **One dominant moment.** Identify the strongest emotional element in the brief (a symbol, a physical detail, a phrase, a texture) and give it **a full-bleed section where typography recedes**.
6. **Copy faithful to the brief.** Sentences in the tone of voice defined in `*_soul.md`. Follow the "Writing guidelines" in `*_experience.md` literally if they appear. Don't invent claims.

## Suggested structure (indicative, not rigid)

Adapt to the brief; if you need to reorder, merge or remove blocks, do it.

1. **Hero** — wordmark/name, a discreet subtitle line, a background image or texture. No loud button. Minimal nav.
    
2. **Anchor phrase** — if the brand has a tagline or emblematic phrase in `*_soul.md`, give it a full-screen section.
    
3. **Who they are / what it is** — editorial block with 2–3 paragraphs rewritten from `*_soul.md` as prose, interleaved with images in asymmetric composition (not a boring symmetric grid).
    
4. **The central element** — a block dedicated to the main emotional motif of the brief (whatever is most cited in `*_experience.md`).
    
5. **Ratings & most-mentioned attributes (TripAdvisor-style, required)** — a structured trust block built only from real data in `*_operations.md` (overall score, total reviews, source platform) and `*_experience.md` (the "Most cited attributes" table and the real use cases). Two columns on desktop, stacked on mobile:
    
    - **Left column:** the headline score as a large display-serif number (e.g. `4.3 /5`), a row of unicode stars reflecting that score with the empty stars dimmed (not removed), the total review count + source in small uppercase tracked caps (e.g. `1,486 REVIEWS · GOOGLE`), and a short italic note on the language/source mix below it (one or two sentences max).
    - **Right column, top — "Most mentioned":** 5–8 attribute rows, each a three-track grid of `name · thin horizontal bar · star count`. The bar fills (left-to-right, animated on scroll into view) in an accent color from `*_visual.md`; the star count beside it uses filled stars + dimmed empty stars so the rating still reads at a glance. Order the attributes by the frequency given in `*_experience.md`.
    - **Right column, bottom — "Good for":** a single row of small uppercase pill tags with thin borders (no fill, no shadow), pulled from the real use cases described in `*_experience.md` (e.g. _Solo work_, _Couples_, _Slow mornings_, _Photography_, _Reading_, _Digital nomads_).
    
    No card shadows anywhere. No invented numbers or attributes — every value must come from the inputs. This section replaces the older prose-testimonials block by default; only fall back to verbatim testimonials if `*_operations.md` lacks rating data **and** `*_experience.md` lacks a frequency/attributes table.
    
6. **Offering / menu / services** — curated selection from `*_operations.md`. Short descriptions. Prices only if they fit aesthetically.
    
7. **People / human detail** — if the brief identifies a strong human detail (staff, founder, ritual, community), a brief section for it.
    
8. **Visit / contact / use** — practical data from `*_operations.md`: address, hours, phone, best times, social links. Optional map embed.
    
9. **Footer** — tiny. Wordmark, one line, discreet credits.

## Technical requirements

- **A single `.html` file**, self-contained. CSS in `<style>`, JS in `<script>` if needed.
- **Responsive.** Mentally test at 375 px, 768 px and 1440 px.
- **No heavy frameworks.** Vanilla. Google Fonts is allowed; GSAP via CDN is allowed if an animation justifies it.
- **Animations** consistent with brand tone: scroll reveals, subtle parallax, discreet hover states. Nothing that bounces or sparkles by default.
- **Accessibility**: sufficient contrast, `alt` on every image, correct heading hierarchy, visible focus states.
- **Performance**: `loading="lazy"` on images, don't load anything that isn't used.

## Final reminders

- Read `frontend-design` before starting and commit to **one** aesthetic direction. Don't mix three styles.
- If torn between two design options, pick the one more aligned with the **personality** defined in `*_soul.md`, not the more "modern" one.
- Pick a language for the copy (the brief's language, usually) and keep it consistent.
- **Don't invent data.** If something isn't in the four inputs, it doesn't appear on the site.
